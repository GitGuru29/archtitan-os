1. Introduction
Modern software development demands computing environments that are performant,
minimal, and purpose-built for development workflows. General-purpose operating
systems such as Windows 11, macOS, and even mainstream Linux distributions carry
significant overhead from background services, telemetry, and features irrelevant to
developers — all of which translate into wasted CPU cycles, memory pressure, and
context-switching friction.

TitanArch is a custom Arch Linux-based distribution built from the ground up as a
developer-first operating system. Unlike distros that patch or configure an existing
environment, TitanArch is constructed using archiso with deliberate component
selection at every layer — from the base system through the compositor, system
services, and companion tooling. The result is an OS that is lightweight by design,
intelligent in resource allocation, and equipped with developer-centric utilities that do not
exist in any other distribution out of the box.

The project encompasses a full custom ISO that boots successfully on real hardware and
virtual machines, a TUI installer written in Bash with full ANSI rendering, a context-aware
performance analyzer and resource allocator, an AI-driven project analyzer, an automated
hybrid GPU switching mechanism, the Neon Monitor hardware dashboard, and
TitanShare — a cross-platform peer-to-peer file transfer system comprising a C++ Linux
daemon and a native Android application.

2. Problem Statement

Developers working on Linux face a recurring set of friction points that are largely
unsolved by existing distributions:

•

•

•

•

•

High idle resource consumption from GNOME, KDE, and comparable desktop
environments — often consuming 800MB–1.5GB RAM at idle before a single
development tool is launched.
No built-in workflow-awareness: the OS treats a compile job the same as watching a
video. CPU governor, I/O scheduler, and memory pressure parameters are static
regardless of what the developer is actually doing.
Hybrid GPU setups (Intel iGPU + NVIDIA/AMD dGPU) require manual configuration,
third-party tools, or proprietary utilities. There is no seamless user-space switching
without driver-level hacks.
Cross-device file transfer between Linux and Android remains fragmented — MTP is
unreliable, KDE Connect is heavy, and cloud-sync tools introduce latency and privacy
concerns for local-only workflows.
Arch Linux's renowned minimalism comes at the cost of a steep setup barrier. There is
no streamlined path from ISO to productive developer environment without hours of
manual configuration.

TitanArch is designed to close these gaps with purpose-built solutions at the OS level rather
than patching them with external tools.

5. Research Gap Analysis
5.1 No Developer-Optimized Linux Distribution Exists
Existing Linux distributions target either general desktop users (Ubuntu, Fedora) or
maximum minimalism (Arch, Gentoo). No distribution combines Arch's minimal base with
purpose-built developer workflow tooling, automated hardware management, and crossdevice communication at the OS level.

5.2 Static Resource Management in Linux
Linux kernel schedulers and CPU governors operate without application-context
awareness. Developer workloads — compile jobs, IDE sessions, containerized testing —
have distinct resource profiles that no current distribution dynamically recognizes or
responds to. TitanArch's context-based performance analyzer fills this gap.

Page 4 of 14

TitanArch — Developer-Focused Linux Distribution | Final Year Project Report

5.3 Hybrid GPU Management Remains Unsolved on Linux
Intel/NVIDIA and Intel/AMD hybrid GPU setups on Linux require manual PRIME
configuration, proprietary utilities (NVIDIA optimus-manager), or complex xrandr
scripting. TitanArch's GPU switcher automates this at the user-space level, providing
seamless switching without driver modification.

5.4 Local Android-Linux File Transfer Has No First-Party Solution
MTP, KDE Connect, and cloud sync tools all have limitations for developers needing fast,
offline, peer-to-peer file transfer between Linux and Android. TitanArch addresses this
with TitanShare — a purpose-built system using mDNS device discovery, a C++ daemon
on Linux, and a native Kotlin/Jetpack Compose Android application.

5.5 No AI-Assisted Developer Environment at OS Level
AI-assisted development tools exist as editor plugins (GitHub Copilot, Cursor) but none
are integrated at the OS/environment level to analyze project structure and recommend
tooling configuration. TitanArch's AI-driven project analyzer operates at the system level,
independent of any specific editor.

5.6 No Native Android Screen Mirroring on Linux
Existing Android screen mirroring solutions on Linux (scrcpy, ADB-based tools) require
USB debugging, manual ADB setup, or rely on X11-only rendering. No solution integrates
natively with a Wayland compositor, reuses existing device pairing infrastructure, or
operates without ADB dependency. TitanMirror addresses this by building on
TitanShare's mDNS pairing and delivering a Wayland-native streaming client.

6. Proposed System: TitanArch
TitanArch is a complete, bootable, installable Linux distribution built on Arch Linux using
archiso. It is not a configuration layer over an existing distro — it is a purpose-built OS
whose component selection, system services, and companion applications are all
designed around developer workflow requirements.

The system ships with a Hyprland-based Wayland compositor environment, a full suite of
custom system services written in C++ and Python, a TUI installer in Bash, and

companion applications: Neon Monitor (hardware dashboard), TitanShare (cross-platform
file transfer), and TitanMirror (Android screen mirroring). An AI-driven project analyzer
and automated GPU switcher complete the developer tooling layer.

7.2 Base System Layer
The ISO is built using archiso with a minimal, curated package selection. Non-essential
services are disabled at build time. The filesystem uses BTRFS with subvolume layout
enabling snapshot-based rollback. Boot configuration targets both UEFI and legacy BIOS
systems.

7.3 Desktop Environment Layer
Hyprland is selected as the compositor for its Wayland-native design, low GPU overhead,
and scriptable configuration. The desktop environment is configured for keyboard-driven
workflows with tiling window management, custom Waybar status bar integration, and
minimal visual overhead.

7.4 System Services Layer
All core system intelligence lives in this layer as systemd-managed services. The
context-based performance analyzer continuously monitors running processes, detects
active workload types (compilation, IDE, gaming, idle), and signals the resource allocator
to adjust CPU governor, I/O scheduler priorities, and memory management parameters
accordingly.

The GPU switcher service monitors application launch events and routing preferences,
switching between integrated and discrete GPU execution paths using user-space DRM
and environment variable management — without modifying driver internals.

7.5 Application Layer
The TUI installer provides a full guided installation experience from the live ISO
environment using Bash with ANSI escape sequences for rendering. TitanShare
comprises a C++ Linux daemon that handles mDNS device advertisement and discovery,
secure file transfer sessions, and pairing management — paired with a Kotlin/Jetpack
Compose Android application for cross-platform transfers.

8. Implemented Features
8.1 Custom TUI Installer
The TitanArch installer is a fully custom terminal user interface written in Bash using
ANSI escape sequences for UI rendering. It provides:

Disk detection and partition layout selection (auto and manual modes)

The installer operates entirely in the terminal without requiring a GUI environment, making it
suitable for minimal ISOs and headless initial setups.

IDE/editor mode: detected via editor process presence (nvim, code, jetbrains processes)
Gaming mode: detected via GPU utilization thresholds and known game process
patterns

The GPU switcher manages hybrid GPU configurations (Intel iGPU + NVIDIA/AMD dGPU)
at user-space level. It provides:
•

•

Automatic detection of available GPUs via DRM device enumeration
Per-application GPU routing through environment variable injection (DRI_PRIME,

A switchable system-wide default for iGPU-first (battery) or dGPU-first (performance)

The switcher integrates with the resource allocator — Gaming profile automatically routes to
dGPU; Battery profile routes to iGPU — without any manual user intervention.

8.6 Neon Monitor
Neon Monitor is TitanArch's real-time hardware monitoring dashboard. It provides a live
view of:
•
•
•
•
•

CPU utilization per-core and overall, with frequency and governor state
GPU utilization and VRAM usage (Intel and NVIDIA/AMD via respective kernel
interfaces)
RAM and swap usage with pressure indicators
Thermal readings for CPU, GPU, and NVMe devices
Disk I/O throughput and network interface statistics

Neon Monitor is implemented as a lightweight terminal dashboard using C++ with direct sysfs/
procfs reads, avoiding the overhead of intermediary monitoring daemons.

8.8 TitanMirror — Android Screen Mirroring
TitanMirror enables real-time Android screen mirroring directly to the TitanArch desktop
over the local network. It allows developers to view and interact with their Android device
from within their TitanArch workspace without any physical connection or cloud
dependency.

TitanMirror leverages the Android MediaProjection API on the device side to capture the
screen and stream it over the local network to a native Wayland-rendered client on
TitanArch. Device discovery reuses TitanShare's existing mDNS pairing infrastructure —
a previously paired TitanShare device can initiate a mirror session with no additional
setup.

8.8.1 Android Component
•
•
•
•

Background service using Android MediaProjection API for screen capture
H.264 video encoding via MediaCodec for efficient low-latency streaming
TCP stream server advertising availability via mDNS alongside TitanShare
Touch/input event receiver for optional remote interaction support

8.8.2 Linux Client (titanmirror)
•
•
•
•

C++ Wayland-native client rendering the incoming stream as a floating window
Hardware-accelerated H.264 decode via VA-API (Intel) or NVDEC (NVIDIA)
Integrates with Hyprland as a standard Wayland surface — supports tiling, floating, and
picture-in-picture modes
Launched via Waybar shortcut or CLI; device selection from TitanShare paired device list

TitanMirror operates entirely over the local network with no internet requirement, no third-party
services, and no ADB dependency — making it a natural extension of the TitanArch crossdevice ecosystem alongside TitanShare.

subsystem (installer, performance services, GPU switcher, TitanShare, Neon Monitor) is
developed as an independently testable module with defined interfaces to adjacent
components. Integration is performed incrementally with validation at each milestone.

12. Current Limitations
•

•
•

•
•

GPU switching operates at user-space level via environment variable injection and DRM
enumeration. Kernel-level GPU scheduling (as in Windows WDDM) is out of scope for
this implementation.
TitanShare cross-device features require both devices to be on the same local network.
WAN transfer and relay-based fallback are planned for future development.
The AI project analyzer currently uses heuristic-based file analysis. Integration with a
locally-hosted LLM backend (e.g., Ollama) for deeper inference is targeted as a post-FYP
enhancement.
Cloud synchronization and remote access features are not included in the current
implementation scope.
The Android application currently targets TitanArch Linux as the peer device; iOS support
is not planned.

14. Conclusion
TitanArch represents a holistic approach to the developer operating system problem.
Rather than configuring or theming an existing distribution, it constructs a complete
system from the Arch Linux base upward — with every component selected,
implemented, and integrated for developer workflow efficiency.

The project delivers a bootable, installable ISO with a TUI installer, a context-aware
performance management layer, automated hybrid GPU switching, a real-time hardware
monitoring dashboard, an AI-driven project analyzer, a cross-platform peer-to-peer file
transfer system spanning Linux and Android, and TitanMirror — a native Wayland
Android screen mirroring client. Each component addresses a concrete gap identified in
the research and competitive analysis.

TitanArch demonstrates that a small, focused team can produce a complete, opinionated,
and technically sophisticated Linux distribution targeting a specific domain — and that
the resulting system has genuine advantages over general-purpose alternatives for its
intended user base.
